My-Tiny.Net :: Networking with Virtual Machines



Configuring our Virtual Machines

Once we have a common base platform, we can use some scripts to configure and add software packages that our servers need to perform their roles.

A partial setup to get you started with good examples is provided - it's up to you to finish the configuration and enhance it

In this Lab Exercise we use a script to set things up automatically: we will have dnsmasq on the Gateway as a DHCP and name server, and all of our other hosts will get dynamic addresses from there. In the next Lab Exercises we will finish the mail configuration, and after that the LDAP and SSL configuration to complete our TinyNet.

The standard configuration files are distributed as an ISO image file that you can mount as a CD on your virtual machine, and then run a script to put everything in its proper place.

IMPORTANT
We want to turn off the VirtualBox internal DHCP server for the Host-Only interfaces, because our TinyNet will be using dnsmasq on the Gateway. You should have done this when you created your ToClone VM. Check it now with Global Tools :: Host Networks, and also make sure the IP address is 192.168.56.n (where n is usually one).

Create our VMs

In our previous lab exercises created one Virtual Machine and did some initial configuration. Now we will use VirtualBox to "clone" that VM into others that we can configure as Gateway, WebServer, MailHost, and LDAPhost (like a "VM factory").

Before we clone, let's get the configuration CD in the drive so we don't have to do that for each VM individually. Do this with NO VMs running.
  1. At the virtualBox main screen, choose your ToClone VM and select Settings > Storage
  2. Click the CD (circle) icon under IDE Controller
  3. Click the Browse (folder) icon next to the CD/DVD Device listbox
  4. Browse to location of the Conf.iso image and select it.
This is equivalent to putting a real CD into the drive; since it is a file rather than an object, several machines can use it at the same time.

Now doublecheck Settings :: Network to make sure Adapter 1 is Enabled and Host-Only, and that NO OTHER Adapters are Enabled.

Start manufacturing! At the Virtualbox main menu, choose Machine and Clone to create four VMs: Gateway, WebServer, MailHost, and LDAPhost. Make each one a Full Clone, and BE SURE TO Reinitialise the MAC address so each VM will have a unique (layer 2) identity on the network.

Now we configure the virtual machines one-by one. The Gateway has a couple of extra steps, and must be done first; the rest are simple and all the same.

Configuring the Gateway

Since the gateway is the central point that links all of our subnets, it needs extra network interfaces. At the VirtualBox main screen, highlight the Gateway VM, use the big orange icon for Settings :: Network and change Adapter 1 to Bridged and Enable Adapter 2, 3, and 4 as Host-Only.

Start the Gateway VM, log in as root, start mc, and navigate to /media/cdrom.

Highlight SetRole.sh, press [Enter] (we know the "executable" bits are set because it is "green star"), and configure as Gateway.

IMPORTANT:

For all of our other VMs we let the system automatically reboot at this point, but there are two things we want to do before that on the Gateway, so press [Esc] or choose Cancel to return to mc.

[ 1 ]  Navigate to /etc and then use [F3] to View /etc/HOSTNAME. This is the "proper" name for the host, which looks a little bit cryptic - see Server Roles :: DNS & DHCP for details about the TinyNet naming scheme, along with an explanation of how it works in practice.

Now use [F4] to Edit /etc/hosts. On the Gateway this defines "aliases" that we can use instead of the proper name in /etc/HOSTNAME. On the other machines this file is almost empty, because their aliases are managed by dnsmasq.

There is a warning in /etc/hosts about hostnames with no "dot", but somehow someone still got it wrong! So,
  1. Add gw.tinynet.edu at the end of the first line, and
  2. Add gateway.tinynet.edu at the end of the third line
  3. Save the file with [F2] and exit the editor with [F10]

[ 2 ]  The other thing we need to do is fix the DHCP Client Daemon (dhcpcd) configuration for the Bridged interface. When this service starts it tries to be "helpful" by automatically identifying a nameserver and writing the address to /etc/resolv.conf. This works fine for most of our VMs, but on the Gateway it "steals" control over name lookups away from our dnsmasq nameserver.

Fortunately, the fix is simple.

First, use [F8] to delete /etc/resolv.conf

Then use [F4] to open /etc/dhcpcd.conf in the mc editor, move all the way down to the very last line, and change it to read
nohook resolv.conf, wpa_supplicant


Save the file with [F2], exit the editor with [F10], and exit mc with [F10] again. Now we can reboot to get the new configurations in place.



When the Gateway finishes rebooting, log in and start mc. Use [F3] to View the files in /etc/dnsmasq.d that control aspects of the DHCP server, DNS, and logging. Documentation is embedded in the files.

Now use [F4] to Edit /etc/dnsmasq.d/cnames. Take note of how the naming scheme works, what aliases are already defined for the other servers, and how you can define new aliases.

We want to create a new alias (cname) for the mail server.

Press [F3] and look for [B---] in the top status bar which means you are marking a block. Use the arrow keys to highlight the whole cname=mailhost.tinynet.edu line and press [F3] again at the end of the block.

Press [Enter] to open a blank line (top status bar will now show [BM--]), and press [F5] to paste in the block. Then press [F3] until the top status bar just shows [-M--] (twice is usually enough), which means you have stopped marking blocks of text. (yes, that's clunky, but mc does so many good things we just have to forgive this one)

Now just change mailhost to mail so there is a second alias for this host. Save the file with [F2], exit mc and restart dnsmasq to get the new configurations in place.

/etc/rc.d/rc.dnsmasq stop
/etc/rc.d/rc.dnsmasq start


From now on, be sure the Gateway is at the login screen before starting any other servers (no need to actually log in). Also be sure to turn off the VirtualBox internal DHCP server for the Host-Only interfaces, because our TinyNet will be using dnsmasq on the Gateway.


Configuring the Other Servers

This goes quite quickly from the command line
  1. Change the current directory to the CD: cd /media/cdrom

  2. Run the script ./SetRole.sh
    Remember - Linux is CaseSensitive!
     ./  tells Linux that the script to run is in the current directory

  3. Now reboot ... But Wait!
    Before that, let's get set up to take a live action look at the network startup process.
Log in to the Gateway, and use the clear command to get a blank screen.

The Logfiles page under Orientation on the menu shows where each application saves a record of its activity. We can watch live updates of DHCP activity by running this command on the Gateway:

tail -f /var/log/dnsmasq.log

and then booting another server - move the VM windows so you can see both at the same time.

When the new VM reaches the network initialisation stage in its bootup cycle, the Gateway will show dnsmasq checking the hostname against its lists of address ranges for net-a, net-b, and net-c with three DHCPDISCOVER messages (that only show the MAC address), and then assigning an appropriate address with DHCPOFFER and DHCPREQUEST (that show both the MAC and the IP address), and finally DHCPACK, which also shows the hostname.


Once you have all four machines configured individually, they are ready to take on their roles in the network.

EXTREMELY IMPORTANT
  1. Make sure the VirtualBox DCHP is turned off for Host-Only network interfaces

  2. If your VM is not shut down properly it will become corrupted and you will have to recreate it.
    NEVER close your VM by simply closing the window (except in an emergency).
    Use poweroff at the command prompt, or go to the
    VirtualBox menu at the top of the VM window and select Machine then ACPI Shutdown

  3. Always start the Gateway first, and wait until the Gateway has finished booting before
    starting the other VMs. The WebServer, MailHost, and LDAPhost can all boot at the same time.

Since we have dnsmasq running on the Gateway we can also use names on our TinyNet now.
Read up on how to poke around the DNS with man dig, and try it out:

dig www.tinynet.edu

dig gw.net-b.tinynet.edu
OK? Now let's have some fun.

All machines have a text-mode browser called links and a webserver called monkey installed.

 1. On any server, make a list of open (listening) ports. This is one of the few commands you really need to know: just think of the famous flower from Holland (the Tulip)
netstat -tulp or netstat -tulpn

 2. Open a new virtual terminal with [Alt][F2] and start htop to see the PID and owner of the Monkey process.

 3. Open a new virtual terminal with [Alt][F3] and start links. Press [Esc] to get the menu, then retrieve the default web page using the loopback address with the URL http://127.0.0.1/

 4. Start links on any other server and retrieve the Monkey index page using the cname for another (running) server rather than an IP address.

 5. Retrieve the Monkey index page from your WebServer using your host system browser (Chrome, Safari, Firefox, Edge ...) and one of the WebServer IP addresses - either one will work. [ You cannot use a cname because your host system does not know how to use the TinyNet DNS, but you can always contact a server on the same subnet! ]

 6. Use mc to take a look at the Monkey configuration files in /etc/monkey, and poke around in /var to find where Monkey serves webpages from. Hint: find the Server_Root directive in /etc/monkey/monkey.conf

www.w3schools.com/html/html_basic.asp
is a great place to get started with understanding how web pages work!
