The X-Windows System


X-Windows is a generic network-aware windowing system, that other applications (clients) talk to provide a graphical user interface (GUI).

There are three major parts to an X-Windows system that can be mixed and matched: X itself, Display managers, and Window managers. Desktop environments bundle these together with a lot of utilities, and that's what most people pay attention to. But, let's start at the bottom and work our way up.

X itself

The very first thing that runs is the actual X Window System, usually just called  X . It's a set of (very complex) libraries that manage the hardware interfaces, fonts, icons, and inter-process communication required to render graphics onto a screen. Its modular and extensible design has led to different implementations, of which X.org is currently the most popular for Linux.

X itself is called a server, because it serves requests by clients. In X, the client is any program, and the server is what is touching your video card. This forces us to extend the concept in our mind a bit: X runs invisibly in the background, while a whole bunch of programs running locally and across the network take advantage of the GUI services it provides.

Display manager

The first client that generally runs is the Display manager (DM), which gets X running before you log in, handles authentication, and keeps X running after you log out. Visibly, all they do is give you a nice prompt for your username and password, and then start your windowing environment of choice. The reason they are separate programs is to allow us to remotely log into another computer over the network. This is a complex enough function (it uses a special protocol called XDMCP) to make it more sensible to make the DM a fully standalone program.

People like DMs because they are specially programmed to open windows that look like they were opened by a particular window manager, which gives a consistent look-and-feel. So, while there are lots of DMs (KDM, GDM, XDM, Slim, lightdm to name a few) they all serve the exact same function, and you can use pretty much any one you want to start any window manager you prefer.

The DM is not really necessary; we can start a session manager in a script after a traditional textmode login to be the initial X client. The big drawback of the DM is that you have to modify your bootloader to bypass the default login screen by using a kernel parameter to set the runlevel: traditionally "runlevel 3" is standard multi-user mode, and "runlevel 5" starts the DM. Linux distros that use the systemd utility instead of /etc/inittab take a kernel parameter like systemd.unit=multi-user.target for a console login or systemd.unit=graphical.target to use the DM.

Window manager

Once you've correctly identified yourself to the DM program, it starts the window manager (WM): a client with special privileges to move other windows around. The WM provides the user interface for windows: opening, moving, minimizing, maximizing, closing windows, borders and buttons, keyboard shortcuts, etc. Other clients like file managers, panels, system monitors and so forth open windows that the window manager will decorate and lay out according to its configuration.

We should note that all these applications may or may not interact in special ways. While some higher level standards exist, and KDE, Gnome and other projects provide various utility libraries and services which can provide consistent looks and behaviours beyond the basic window control that the WM handles, differing levels of integration and cooperation in each programmer's implementation can cause things like drag-and-drop and cut-and-paste to be a bit hit-and-miss.

Desktop environment

Desktop environments (DE) are a collection of standards and libraries, and a suite of applications intended to have a reasonably consistent user interface, and to work well together. KDE and Gnome are the big two in the Linux world, along with XFCE and LXDE which are the best-known "lightweight" DEs. Most Linux distros have a standard DE, so when you install the distro you don't have to make choices about display manager and window manager -- you get one by default: GDM and Metacity for Gnome, KDM and Kwin for KDE, etc.

Many people choose to not use a desktop environment at all, and just use one of the dozen or so window managers available (twm, openbox, fluxbox ...). However, the big advantage of a DE is that they are designed for system-wide configuration, and their apps are compiled to share a lot of binary libraries (which saves memory and avoids hassles with dependencies). If you mix apps in unaffiliated apps, you can expect to have to do things in different places to change fonts, for example. On the other hand, this integration can make it quite difficult to replace some apps, like the Thunar file manager in XFCE.

Application Libraries

The last thing to know is that there are two major sets of libraries that developers use when they create apps for X,  gtk  and  QT , which are completely incompatible and very sensitive to versions. This makes configuration tricky sometimes, because the DE is built with one (gtk3 for example) and the app you absolutely must have is built with another (like gtk2, QT4, or QT5). The usual solution is to make sure you have two complete versions of each one installed, and be ready to search the blogs for obscure but essential configuration tweaks. As you might imagine, lots of people are unhappy with this situation - but it has been like this for a long time now, and it seems clear that developers are not going to give up their freedom to create using their favourite tools.

mytyVM XFCE

The myty-xwin.iso image, available from mytyVM Images on the menu will install the XFCE desktop environment with X.org underneath, configured to start X with a session manager rather than a DM. The install-xwin.sh script will insist you have 400mb free space, so use your Base.iso to create a new VM exactly as described in Getting Started::Creating VMs on the menu, except (a) give it 384mb RAM and use "Dynamically expanding storage" of 980mb in VirtualBox, and (b) in cfdisk allocate 950M to dev/sda1 and 30M to dev/sda2.

The install-xwin.sh script will take care of everything required to get the VM up and running on net-b if it is not configured already, create a new user with scripts in the home directory for starting X, and put a note on the login screen about how to get started.

The  .bashrc  and runxwin scripts are installed in /etc/skel so new users you create on this VM will also be able to run X. You can uncomment the line in /home/xuser/.bashrc to start X automatically as soon as you put in the password (just like a DM).

The mytyVM XFCE setup is minimal, because it is really only here to support the Contiki IoT extension (-Under Construction-). In addition to standard XFCE apps, the featherpad editor is always installed, and the install script gives you the option to install Wireshark and/or the Midori browser. But that's it - if you want more, you should probably use a different distro (Lubuntu/LXDE is nice).

Even though (or Since) the installation is minimal, you can still have some fun changing the icons and themes.
