Setting up our "To Clone" VM

First Things First

We need to understand some basic concepts to get our system services configured.
We won't go into all of the details here, but the quick list is:
  • System accounts, owners, and groups
    Every file and every process has an owner, and every owner belongs to a group. Normal accounts have a username and password; system accounts have no password. The primary purpose of system accounts is to own files and processes, so access can be controlled through file permissions. The root account is a special case: it has access to everything.

  • File permissions (mode)
    • Linux has three levels of file permissions: read [r], write [w], and execute [x].
      These have values: r=4 w=2 x=1 which add up to 7.
    • When the executable bit is set on a file, Linux will treat it as a command. When the executable bit is not set on a directory (folder), Linux will treat it as a hidden directory.
    • Permissions can be applied to files and directories at three levels: owner [u], group [g], and world [o]
      (u is for user, o is for others)
    For example, if a file has owner nobody and group nobody, and permissions are 660 (rw-rw----) only the application running as nobody (and root) can open, change, or delete the file.

  • Symbolic links
    A "symlink" is like a Windows "Shortcut": it allows one file to have multiple names, possibly in different directories. (quite convenient).
These are discussed in more detail in the Key Concepts page under Server Roles on the menu. Our goal now is to jump in and use them to get our system up and running as quickly as possible. Also, these common tasks are much easier with the mc file manager, which we used briefly to copy the base operating system files from the CD image to the hard disk.

Common Configuration

There are a few things we need to do to make some common services available on each of the servers we will create from our "ToClone" VM (Gateway, WebServer, MailHost, LDAPhost). We'll do the first steps in mc.
  1. /etc/rc.d/rc.sshd: Set the execute bits for everyone

    The directory /etc/rc.d/is a special place in our filesystem where all of the scripts that are executed at boot time are stored (use [F3] to see how this works in rc.M and rc.inet2). We want rc.sshd to run at startup, so highlight this filename and press [F9] to get to the Menu, then use the arrow keys to select File and cHmod. This screen shows the file permissions on the left and a summary of attributes on the right. Permissions can be turned on and off using [Space] (watch the numeric representation of the mode on the right change as you do this!). Put [x] beside the "execute" line for all three (755), and we're done.

  2. /var/run: Set the read, write, and execute bits for everyone and Set the sticky bit

    Same steps as /etc/rc.d/rc.sshd except this time we change permissions on the directory. Setting the "sticky bit" (t) on the directory (1777) allows world write, but files can only be deleted by the owner. For details, see the Key Concepts page under Server Roles on the menu.

  3. /usr/local/sbin/banana: Symlink as /etc/rc.d/rc.monkey

    All of our VMs start the monkey webserver in /etc/rc.d/rc.local, but it is nice to have a proper script to stop and restart it when we change the configuration file. Somehow this got put in the wrong place, so we can create a "shortcut" to get it where we want it. All we need to do is get /etc/rc.d/ on one side in mc and /usr/local/sbin/ on the other side (use [Tab] to switch). Highlight /usr/local/sbin/banana and press [F9] to get to the Menu, then use the arrow keys to select File and Symlink. mc automatically volunteers to create the symlink on the other side, so just change the filename (last part) to rc.monkey and press [Enter].

  4. /etc/rc.d/rc.xinetd: Set the execute bits for everyone and Symlink as /etc/rc.d/rc.inetd

    Another service we always want; create the symlink rather than editing /etc/rc.d/rc.inet2. This is simple if you have the same directory on both sides.

  5. /etc/xinetd.d/telnet: [Edit] Disable = no, Only From = 127.0.0.1

    Use [F4] to edit. See the xinetd page under Utilities on the menu for the full story.

  6. Prepare the webserver logfile
    Let's do this all from the command line, since we cannot do the first step from mc
    a.Create a new file: touch /var/log/httpd.ERRORS
    b.Use [up-arrow] and edit: chmod 664 /var/log/httpd.ERRORS
    c.Use [up-arrow] and edit: chown nobody:nobody /var/log/httpd.ERRORS
    d.Check the result: ls -l /var/log
All Done! We're ready to create our servers using this one!


It is a good habit to have three virtual terminals on each VM:
  • one with a plain shell for entering commands,
  • one with mc for reading log files, configuration files, etc.
  • one with htop for watching processes,
  • and maybe one more for reading man pages too!
