Debugging the eMail service


Our test strategy is to do one thing at a time, so we start by speaking SMTP with the MailHost to make sure the local delivery is working.

BUT when we look in /var/log/maillog we see a lot of messy error messages. These can be hard to figure out, but the simple strategy is start at the bottom, look for things you recognise, and then think through the problem.


First, notice the message that says
Can't open file ... Permission Denied
What do we do?

When we use mc to look at the permissions for dovecot.IMAP with [F9]  File  cHmod we see on the left that the owner and group can write to the file, and on the right that the owner and group is root

When we look at the table in Orientation::LogFiles, we see that dovecot.IMAP and dovecot.LDA are there for dovecot - but what it does not say is that IMAP is for mailbox messages, and LDA is for "Local Delivery Agent" messages.

The main configuration file for dovecot is /etc/dovecot/dovecot.conf and we can see there that the "Internal user for unprivileged processes" is dovecot while the "System user and group used to access mail" is vmail, so this is most likely to be the proper owner.

Even though the "Can't open file" message is in the postfix logfile, we know that postfix relies on dovecot to deliver the mail, so the message must be passed back to postfix when dovecot cannot open its logfile.

So, the solution is to use mc and [F9]  File  chOwn to change the owner and group to dovecot for dovecot.IMAP and to vmail for dovecot.LDA

If we tried the mail again now, we would get another permissions error:
net_connect_unix(/var/run/dovecot/stats-writer) failed: Permission denied
Dovecot creates this file for its internal use when it starts up. When we check, we can see this file has 660 permissions, the owner is root, and the group is dovecot. The problem here is that the both the IMAP and LDA processes want to use this file (it is actually a "unix socket", similar to a "named pipe", but we can explore that later).

Since the group already has read and write permissions, the best way to fix this is to simply add the users dovecot and vmail to the lines in /etc/group with the same names. This is easiest from the command line: let's check the current entries, make the changes, and check again. Remember to save yourself some typing with [Up Arrow] to get a previous command back ...

tail /etc/group

usermod -G dovecot,vmail dovecot

usermod -G dovecot,vmail vmail

tail /etc/group
Now we are ready to try the mail again, but before that let's check two more things that the RoleConfig script should have taken care of:
  1. the file /home/vmail/mail-pwd has owner vmail and permissions 660
    use ls -l /home/vmail/* or mc to check

  2. the directory /home/vmail is world-writeable with the sticky bit set
    use find / -perm /1000 for a list of everything that has the Sticky Bit set
Check Getting Started :: First Things First if these are incorrect and you don't remember how to fix them.


"User Unknown"

Following our one thing at a time strategy, we have a small set of accounts that dovecot will deliver mail for - later we will have dovecot deliver mail for everyone in our LDAP directory.

The filename is specified in /etc/dovecot/dovecot-auth.conf down in the ## Authentication databases section: 
  ...LDAP stuff...
  passdb {
    driver = passwd-file
    args = /home/vmail/mail-pwd
  }
  ...LDAP stuff...
  userdb {
    driver = static
    args = uid=vmail gid=vmail 
  }
We sent our mail to mailadmin@mailhost.tinynet.edu, but when we look at /home/vmail/mail-pwd we find the account name is
mailadmin@mail.tinynet.edu:{PLAIN}admin::::::

As it says in the comments, this is an important address because /etc/postfix/virtual_alias maps all of the email addresses required by the Internet standards to this mailbox. Putting all of this mail in a single place makes it convenient to manage.

So, all we need to do is change the account to mailadmin@mailhost.tinynet.edu:{PLAIN}admin::::::

IMPORTANT: these account names can only use numbers, dot, dash, and LOWERCASE letters.

While you are here, add your own name to the list by copying and pasting the mailhost line, and put your account name before the  @ . Your unencrypted (PLAINtext) password is admin, which you can also change if you like. The extra bunch of  :  are for fields we do not use.

Dovecot automatically notices new users immediately after they're added, (no need to restart to get the changes in place like normal). So, we're ready to try the mail again!


Back in /var/log/maillog look down for the Connect from localhost message. The next line (and a few after) have the message identifier you saw when you sent the message you typed.

There are lots of messages about this being undeliverable, and some double-bounce messages that mean the MailServer tried to return the message to example.com by sending it first to the Gateway, but this is just a fake domain for testing so the Gateway bounces it back to the MailServer, and eventually after a few of these round trips it either gets delivered to mailadmin or they just give up and discard the message.

So, all of the critical errors are fixed. Postfix complains about "reject after permit" in its configuration file but refuses to start if it is not there, so never mind.
